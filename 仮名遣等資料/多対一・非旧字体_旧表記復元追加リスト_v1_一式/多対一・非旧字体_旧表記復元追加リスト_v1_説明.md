# 多対一・非旧字体 旧表記復元追加リスト v1

> **監査状態（#62）: RESEARCH CANDIDATES / NOT EXECUTION AUTHORITY**
>
> この一式はAI調査由来の候補集合であり、generic core / KiNoTch profileへ一括投入しない。出典欄の多くはサイト単位の候補で、各行の旧表記関係を直接立証していない。また同一入力 `弁口` に `辯口` と `瓣口` の競合が存在するため、`実行採用=TRUE` を安全性判定として扱わない。

## 目的

このリストは、告示PDF由来の「同音漢字書換」表とは別に、旧字体化・字体整理・異字統合のうち、一字対応だけでは復元できないものを語単位で探索した追加候補である。

## 採用方針（候補生成時の方針）

- `学→學`、`国→國` のような純粋な一字対応は除外し、一字対応表側へ回す。
- `弁→辯/辨/瓣`、`台→臺/颱`、`余→餘/余`、`予→豫/予`、`欠→缺/欠`、`芸→藝/芸`、`虫→蟲/虫`、`缶→罐/缶` のように、一つの現代字から復元先が分岐するものを熟語候補として収集した。
- `注→註` は旧字体ではないが、注釈・注記系の旧表記・異表記候補として語単位で収集した。
- 先行の告示PDF系と完全重複すると判断した行は候補生成時に除外した。

## 実装上の扱い

- このCSVをそのまま変換エンジンへ投入しない。
- 語単位・最長一致であっても、同一入力の競合、語義、固有名詞、時代差を個別に解決する必要がある。
- `学芸→學藝`、`灯台→燈臺`、`欠陥→缺陷` のように複数の独立変換を一つの文字列規則へ畳み込んだ行は、canonical ruleではなく回帰例として扱う候補である。
- generic / project-profile の責務判定は #47/#57 と `data/profiles/kinotch/legacy-stage60-classification.json` を優先する。
- 採用は実歌詞のgapから必要になった語を、出典・語義まで再確認してboundedに行う。
